# CI-01 · CI has never been green — restore the gradlew executable bit and gate it

**Priority:** P2
**Effort:** ~0.5 d
**Skills:** `critical-invariants.md` + `testing.md`

## Motivation / context

Every CI run this repository has ever produced failed: 23 runs of `ci.yml`, 23 failures, no
exception. The cause is one number. `backend/gradlew` was recorded in the git index as `100644`,
so a runner checked it out non-executable and every `./gradlew …` step died at once with
`./gradlew: Permission denied` and exit code 126.

That killed the `backend` lane at its first step and the `database` lane at its first Gradle step,
and through `needs:` it killed `CI Gate` — the one status check the branch ruleset for `main`
requires. So nothing downstream of those two lanes had ever executed, and every claim about them
was an assumption. The point of this package is not only to make the pipeline start, but to find
out what was hiding behind a failure that never let it run.

The defect survived because it is invisible from the machine that introduced it: with
`core.filemode=false` — the Windows default — the working tree's permission bits never reach git.
`ls -l` shows `rwxr-xr-x`, `chmod +x` records nothing, and the only place the truth lives is
`git ls-files -s`.

## Current state (honest)

Before this package:

- `backend/gradlew` was `100644` in the index. **No file in the repository was `100755`** — not one,
  including `scripts/verify_image.sh` and every `scripts/*.py` that carries a shebang.
- `.github/workflows/ci.yml` set `timeout-minutes` on none of its six jobs; `codeql.yml` and
  `release.yml` set it on neither of theirs. GitHub's default is six hours.
- `persist-credentials: false` was set on exactly one of the nine `actions/checkout` steps in the
  three workflows — `ci.yml`'s secret scan.
- Every JavaScript action was pinned to a major declaring `using: node20`. GitHub removes Node 20
  from runners on 2026-09-16, so the pipeline was scheduled to break again three weeks after this
  ticket was written, for an unrelated reason.
- `release.yml` verified a strictly smaller set of repository gates than `ci.yml` did, and its
  "Tag does not already exist" step read an unreachable remote as "the tag is free".
- `scripts/_common.py` claimed to be "unit-tested by `tests/test_tooling.py`". That path does not
  exist and never has.

What was *not* wrong, established by running each lane locally (see § Verification): the Kotlin
build, its lint and static-analysis gates, the module-boundary guard, the tests, the frontend lane
end to end, and the whole database lane including the idempotency re-run and the schema-integrity
checks. Nothing was hiding behind the failure. That is a finding, not an assumption — it is what
the local run established, and it is the first time any of it has been observed to pass.

## Approach

1. `git update-index --chmod=+x` on every tracked file carrying a shebang — the wrapper plus the
   thirteen `scripts/*.py`, `scripts/verify_image.sh` and `frontend/scripts/generate-zod.mjs`.
   `gradlew.bat` is excluded: cmd.exe consults no permission bit.
2. Add `scripts/lint_executable_bits.py` and run it first in the `repo-checks` lane. It reads the
   git **index**, never the filesystem, because on a `core.filemode=false` machine the filesystem
   answers a different question and answers it reassuringly.
3. Run every lane locally, by its real equivalent, and fix whatever surfaces.
4. CI hygiene, in the same package because each item is a property of the same three files:
   per-job timeouts, `persist-credentials: false` wherever the token is not needed, and pin
   alignment with the sibling repositories.

## Acceptance criteria

- [x] `backend/gradlew` is `100755` in the git index, and every other tracked file with a shebang
      with it.
- [x] `scripts/lint_executable_bits.py` exists, runs in `repo-checks` and in `make check-repo`, and
      is **demonstrably red** on three mutated fixtures: the bit removed; the bit set on a file with
      no shebang; and the bit removed *together with* the shebang, which is the escape route a
      shebang-only rule would leave open.
- [x] Every job in all three workflows sets `timeout-minutes`.
- [x] Every `actions/checkout` sets `persist-credentials: false`, except the one release step that
      pushes a tag, which says why in place.
- [x] Every JavaScript action pin declares `using: node24`; the one action left behind states its
      reason at the pin.
- [x] Every `run:` and `uses:` target in all three workflows was swept and exists.
- [x] Each CI lane run locally by its real equivalent, with the results recorded honestly below.
- [x] Independent review (phase 4, run in a sub-agent): 0 BLOCKING findings.
- [ ] **A run of `ci.yml` on `main` concludes `success`.** This is the criterion the ticket exists
      for and the only one that cannot be met from a working tree: it needs a commit and a push,
      which are the operator's to make. Until it is checked, "CI is fixed" is a well-argued
      prediction and nothing more.

## Affected files

- `backend/gradlew`, `scripts/*.py`, `scripts/verify_image.sh`, `frontend/scripts/generate-zod.mjs` —
  index mode `100644` → `100755`.
- `scripts/lint_executable_bits.py` — new gate.
- `.github/workflows/ci.yml` — the new gate step, six timeouts, five `persist-credentials`, pins.
- `.github/workflows/codeql.yml` — timeout, `persist-credentials`, pins.
- `.github/workflows/release.yml` — two timeouts, `persist-credentials`, pins, the gate list brought
  level with `ci.yml`, and the tag probe taught to distinguish "no such tag" from "could not ask".
- `Makefile` — `check-repo` runs the new gate first.
- `docs/ci.md` — the gate's row, and why the pins are SHAs and when they move.
- `docs/docs_map.md` — regenerated for the new heading.
- `scripts/_common.py` — removed a claim of a test file that does not exist.

## Verification

The machine this ran on has no JDK and no `psql`, so the JVM and database lanes ran inside
containers rather than natively. Same commands, same images CI uses.

| Lane | How it was run | Result |
|---|---|---|
| repo-checks | `make PY=py check-repo` | green, all ten steps |
| backend | `eclipse-temurin:21-jdk` container: `./gradlew ktlintCheck detekt checkModuleBoundaries`, then `test`, then `build -x test` | `BUILD SUCCESSFUL` ×3 |
| frontend | `yarn install --frozen-lockfile`, `api:generate` + drift check, `lint`, `typecheck`, `test:coverage`, `build` | green; no client drift; coverage 89.85 %, lowest file 87.61 % against an 80 % floor |
| database | `postgres:16-alpine` matching the CI service definition; `lint_sql.py`, migrate, migrate again, `schema_integrity.sql` | 5 migrations applied, then `Applied 0 migration(s)`, then `Schema integrity: OK` |
| secret-scan | not run | gitleaks is not installed here; CI-only by design (`docs/ci.md`) |

**Not verified locally, and unverifiable from here:** that the bumped action pins behave on a real
runner. A pin can only be exercised by a run. The bumps are argued from each action's `action.yml`
runtime declaration and its release notes, and from the sibling repositories already running four
of the six.

## Review record (phase 4)

Run in a sub-agent that did not write the code, against `.claude/agents/reviewer.md`.

**VERDICT: APPROVED — 0 BLOCKING, 7 NON-BLOCKING.**

The reviewer re-derived the diagnosis from the runner rather than from this ticket: 23 runs of
`ci.yml`, 23 failures, and the verbatim `./gradlew: Permission denied` / `exit code 126` in both
the backend and database lanes of the last one. It swept the index independently
(`git cat-file blob | head -c 2` rather than trusting the new linter) and confirmed 16 shebang
files, 16 × `100755`, and no other executable entry; and it reproduced the three mutated fixtures
plus a fourth of its own — `backend/gradlew` removed from the index entirely, caught by
`REQUIRED_EXECUTABLE`.

Fixed in this session:

- **N1** — `release.yml`'s gate list omitted `ci.yml`'s tenth repo-check, the TODO/FIXME grep,
  while a comment, the CHANGELOG and this ticket all claimed parity. The step is now lifted from
  `ci.yml` verbatim, so "byte-identical" is a fact rather than an intention.
- **N2** — `docs/ci.md`'s job-summary row, the one a reader skims, did not list the new gate.
- **N4** — `blob_heads` indexed `split()[2]` unconditionally; a `<oid> missing` record from a
  damaged or blobless object store would have raised `IndexError` past `main()`'s handler and
  shown a traceback instead of the gate's own FAIL line.
- **N5** — this ticket said "ten `actions/checkout` steps"; there are nine.
- **N6** — `${{ inputs.version }}` was interpolated straight into three shell bodies in the
  `verify` job, including the SemVer guard meant to validate it — substitution happens before bash
  parses, so the guard cannot protect the line it is written on. All three now pass the value
  through `env:`. The `build` job still interpolates, deliberately: it runs only once `verify` has
  proved the value is SemVer, and rewriting an untested release path further is a worse trade.

Not fixed, with reasons:

- **N3 — no committed regression test for the new linter.** True, and true of all ten gate scripts
  in `scripts/`; there is no test harness for this directory to hang one on, which
  `scripts/_common.py` now says out loud instead of claiming a `tests/test_tooling.py` that never
  existed. Building that harness is its own package, and inventing one here to cover a single
  script would leave the other nine exactly as they are. Recorded, not ticketed: filing it would
  break the "at most as many tickets as it closes" rule for a gap this session did not create.
- **N7 — no `docs/retro/<slug>.md`.** § 11 asks for one when a P1 or P2 defect took ≥ ~0.5 day to
  *understand*. This one took minutes: `git ls-files -s backend/gradlew` answered it. The half day
  went on proving the four lanes behind it, which is verification, not diagnosis. The repeatable
  check a retro would have produced is `scripts/lint_executable_bits.py`, which exists.
