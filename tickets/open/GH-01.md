# GH-01 · Link branches, commits and pull requests onto tickets automatically

**Priority:** P3
**Effort:** ~2 d

## Motivation / context

A ticket should show the branches, commits and pull requests that belong to it, and it should show
them without anyone pasting a URL. The link that matters most is always the one nobody remembered to
attach.

The shape is settled in [ADR-0010](../../docs/adr/0010-external-references-are-links-not-copies.md):
references, never copies; the integration is an ordinary `agent_actor`, not a new participant kind.
This package implements that and nothing beyond it.

## Current state (honest)

Nothing exists. No table, no domain model section, no port, no adapter. The only part that is already
in place was built for this without naming it: invariant T3 makes a ticket key permanent and never
reused, and gives the reason outright — *"External references (commits, chat, other tickets) must not
silently retarget."*

`agent_actor` also already fits an integration without modification — `owner_actor_id`,
`runtime_hint` as descriptive free text, `contact_url` — so decision 1 of the ADR costs no schema
change at all.

## Approach

1. **Migration** creating `ticket_external_ref` per ADR-0010 decision 2, with its RLS policy in the
   same migration because it is project-scoped. Columns exactly as the decision lists them; the
   omitted ones are the fence, not an oversight. Record it with `python scripts/lint_sql.py --accept`
   in the same commit.
2. **`docs/DOMAIN_MODEL.md`** gains a section for the entity, placed after § 5 (`ticket`).
3. **Registering an installation** creates an `agent_actor` with `runtime_hint = 'github-app'`, owned
   by the human who installed it. No new column, no new kind, no `is_integration` anywhere.
4. **Webhook adapter** in `:api-rest`: signature verified *before* the body is parsed, rejecting a
   missing or malformed signature outright. The acting actor is the installation's agent actor; a
   login found in the payload is never treated as identity.
5. **Key detection** over branch names, commit messages and pull request titles and bodies, matching
   the `project.key/ticket.key` form. Reading a message to find a key is not storing it.
6. **Ticket detail view** renders the references grouped by type, each with its `last_seen_at`, so
   the display says what was last seen rather than asserting a current state.

## ⚠️ To decide before starting

- **Which webhook events.** Recommendation: `push`, `pull_request`, and `create`/`delete` for
  branches. Deliberately **not** `check_run` or `check_suite` — recording build outcomes is inside
  the fence and a legitimate later package, but it is not linking, and folding it in here makes a
  small decision carry a larger one.
- **Where the link removal path lives.** A false positive has to be removable by a human. Simplest
  answer: a capability on the ticket, checked like any other; it does not need its own mechanism.

## Acceptance criteria

- [ ] `ticket_external_ref` carries its RLS policy in the migration that creates it, proved by a test
      that is demonstrably red when the policy is dropped.
- [ ] No column holds a diff, a file's contents, a full commit body or a pull request description —
      checked by reading the migration in review, and stated there in a `comment on table`.
- [ ] The integration is an `agent_actor`. `scripts/lint_invariants.py` passes, and no code path in
      the diff asks whether an actor is an integration.
- [ ] **Attenuation is proved, not assumed:** revoking the owner's write capability on a project stops
      the integration linking there, with no separate revocation step — a paired-negative test that is
      red when the attenuation check is removed.
- [ ] A webhook with a missing, malformed or wrong signature is rejected before the body is parsed,
      and the rejection is tested for each of the three cases.
- [ ] A ticket key appearing in a branch name, a commit message and a pull request title each produce
      exactly one reference, and a repeat delivery of the same event produces no duplicate.
- [ ] Creating and removing a reference each write exactly one `audit_event`, attributed to the
      integration's actor with its owner reachable through the chain.
- [ ] The ticket detail view shows `last_seen_at` beside each reference, at 375 px, actually looked at.
- [ ] `make check` green.
- [ ] Independent review (phase 4, run in a sub-agent): 0 BLOCKING findings.

## Affected files

## Verification

`./gradlew :persistence:test :application:test :api-rest:test` with Docker running. The attenuation
test is run once with the check removed to confirm it goes red. Replay a captured GitHub webhook
payload against the endpoint with a valid signature and with a corrupted one, and confirm the second
is rejected without the body being parsed.
